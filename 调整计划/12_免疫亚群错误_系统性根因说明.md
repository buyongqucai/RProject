# 12 免疫亚群错误 — 系统性根因与逻辑修正

**生成时间：** 2026-07-13  
**数据集：** GSE190856 / GSE207363 / GSE207177（图名上的数据集即出错对象）  
**相关代码：** [`共享脚本/工具_scRNA细胞注释.R`](../共享脚本/工具_scRNA细胞注释.R)、[`共享脚本/工具_scRNA可视化.R`](../共享脚本/工具_scRNA可视化.R)

## 一、现象（您看到的）

| 图 | 问题 |
|----|------|
| `{GSE}_UMAP_免疫聚类.pdf` | 图例是 **0–15 数字**，不是细胞名 |
| `{GSE}_UMAP_免疫谱系.pdf` | 出现 **Endothelial / Fibroblasts**（甚至 Cardiomyocytes / Pericytes） |

您的判断正确：**免疫亚群图只应含淋巴系（T/B/NK）+ 髓系（巨噬/粒/单核/树突等）**，不应出现基质细胞。

## 二、原流水线在做什么（逻辑链）

```text
全细胞 Seurat
  │  annotate_clusters_by_markers(CARDIAC_MARKERS) → celltype + score_* 列
  ▼
subset_immune_recluster()
  │  ① immune_score > 0 取细胞（软筛选）
  │  ② 再聚类 / UMAP
  │  ③ annotate_clusters_by_markers(IMMUNE_LINEAGE) → immune_lineage
  ▼
出图
  │  免疫聚类 → group.by = seurat_clusters（数字）
  │  免疫谱系 → group.by = immune_lineage（本应只有免疫名）
```

错误不是“GEO 数据本身有内皮算免疫”，而是 **我们自己的筛选 + 注释代码写错**。

---

## 三、根因 1（主因）：评分列泄漏

### 旧代码（错误）

```r
# annotate_by_markers 旧逻辑
obj <- score_celltypes(obj, marker_list)          # 写入 score_Macrophages 等
score_cols <- grep("^score_", colnames(meta))     # ← 读到「全部」score_ 列
# 按最高分定细胞类型
```

### 为什么会标出内皮/成纤维？

1. 全组织注释先写入：`score_Endothelial`、`score_Fibroblasts`、`score_Macrophages`…
2. 免疫子集对象 **继承** 这些列
3. 再跑 `IMMUNE_LINEAGE` 时又写入一套 `score_*`（或 `score_Macrophages.1`）
4. `grep("^score_")` **把旧的 CARDIAC 分数和新的免疫分数混在一起**
5. 某些细胞/簇上 `score_Endothelial` 仍最高 → `immune_lineage = Endothelial`

证据：

- `IMMUNE_LINEAGE` **定义里根本没有** Endothelial/Fibroblasts
- 但旧 `immune.rds` 的 `immune_lineage` 列里却有这些标签
- GSE207177 还出现过 `Macrophages.1`（列名冲突副作用）

**结论：** 不是生物学上免疫簇“变成”内皮，而是 **注释函数读错了分数列**。

---

## 四、根因 2：免疫子集软筛选过松

### 旧代码（错误）

```r
cells <- rownames(meta)[immune_score > 0]   # 阈值很松
sub <- subset(obj, cells = cells)
```

后果：全组织已标为 Endothelial/Fibroblasts 的细胞，只要免疫 marker 模块分略大于 0，就会混进“免疫子集”。  
即使注释函数修好，这些污染细胞仍会进图（可能被标成邻近免疫类型或 Unknown）。

实测（修正前）：

| 数据集 | 免疫谱系中非免疫标签细胞数 |
|--------|---------------------------|
| GSE190856 | 557 |
| GSE207363 | 2254 |
| GSE207177 | 4533 |

## 五、根因 3：出图用了聚类编号

```r
plot_umap_clusters(immune_obj, ...)   # group.by = seurat_clusters → 0,1,2,...
```

这不是注释错误，是 **可视化 intentionally 画的是簇 ID**。  
细胞名本在 `_UMAP_免疫谱系.pdf`，但第一张“免疫聚类”图用数字，容易误解。

---

## 六、三因如何叠加

```text
软筛选把基质细胞放进免疫子集
        +
grep("^score_") 把 CARDIAC 分数泄漏进免疫注释
        +
免疫聚类图用数字簇
        =
您看到的两张问题图
```

## 七、已做修正（逻辑）

### 1. 注释：只读「本次」打分列

- 每次注释用独立前缀：`ann_celltype_` / `ann_immunelineage_`
- **禁止** `grep("^score_")` 扫全表
- `score_celltypes()` 强制要求传入 `prefix`，不再默默写全局 `score_`

### 2. 免疫子集：celltype 硬过滤优先

```text
若有 celltype：
  只保留淋巴系+髓系标签
  强制剔除 Endothelial/Fibroblasts/Cardiomyocytes/Pericytes/Smooth_muscle
若无 celltype：
  才回退 immune_score / Ptprc
进入子集后：清除历史 score_/ann_ 列，再重新打分注释
最终断言：immune_lineage ⊆ names(IMMUNE_LINEAGE)
```

### 3. 出图：一律细胞名

- `_UMAP_免疫聚类.pdf` / `_UMAP_免疫谱系.pdf` → `group.by = immune_lineage`

## 八、为何需要改、是否合理

| 问题 | 是否必须改 | 说明 |
|------|------------|------|
| score 列泄漏 | **必须** | 明确 bug，否则免疫图科学上错误 |
| 软筛选基质混入 | **必须** | 免疫亚群定义被污染 |
| 数字簇图例 | **应改** | 不影响统计，但易误导读者 |

这不是“优化锦上添花”，而是 **纠正错误标注**；期刊若审查免疫亚群图，内皮/成纤维出现在“免疫谱系”会被直接质疑。
