01 网络药理学

1. 为何采用这一分析

得到复方靶点并集 F 与药病交集 I₁，作为三源交集的复方侧上游。此步不混入菌群代谢物，避免把网药与网毒/菌群轴做成同一段。

2. 数据来源

数据库：疾病靶点 D 为交付合并集，登记来源包括 GeneCards、OMIM、DisGeNET、CTD 等；成分靶点来自交付网药流水线（含 SwissTargetPrediction 等历史抓取）。

为何用该数据集：与客户交付口径一致，保证后续 I₁ 可复现；不用另开一套疾病库以免「换库即改交集」。

原始路径：01_网络药理学/数据文件/原始数据/（药物数据_复方成分与靶点/、疾病数据_UC靶点多库/）。

处理后路径：01_网络药理学/结果文件/数据文件/（药物/、疾病/ 等）与 01_网络药理学/结果文件/图片文件/；I₁ 基因列表供 03_三源交集_复方UC菌群/ 读取。

3. 筛选标准

I₁=F∩D。|D| 冻结为 1517，不随库更新改动。单药/全药表按交付字段去重、统一基因符号。这样清洗是为了冻结宇宙集，使超几何与置换的分母稳定。

4. 数据处理与函数

合并各成分靶点→去重得 F→与 D 求交得 I₁→出网药阶段图。脚本与阶段报告见 01_网络药理学/。

5. 参数与取值原因

D=1517 为课题锁定（非软件默认）。不在本步引入 SEA/STP 阈值。

6. 输入与输出

输入：交付靶点与疾病表。输出：I₁=291 及网药图。停机：I₁ 为空则不得进入 03。

7. 结果数据与图片怎么读

验收：I₁ 基因数=291。方法版不堆网药长图；细图在 01_网络药理学/结果文件/图片文件/。

8. 解读边界

只写药病重叠候选，不写疗效或菌群机制。

02 网络毒理学·毒性分层（支线）

1. 为何采用这一分析

满足毒性分层支线交付；主线证据仍是 03 的三源共有靶点，不把毒性分层当作对接/MD 的准入门槛。

2. 数据来源

数据库：有害暴露物名单；毒性/不良结局线索来自 CTD、TTD、AOP-Wiki（按计划登记使用）。代谢物有害分层可对照 gutMGene/GMMAD2 注释字段。

为何用：提供暴露物–不良结局线索，供主面板排除既定有害物时引用。

原始 / 处理后：02_网络毒理学_毒性分层/数据文件/原始数据/ 与 02_.../结果文件/数据文件/、02_.../结果文件/图片文件/。

3. 筛选标准

不良结局限定肠屏障损伤、肠道炎症、黏膜损伤/癌变风险（2026-10-07 冻结）。主面板 Tier A 结论排除既定有害物。这样洗是为了毒性支线不污染主交集叙事。

4. 数据处理与函数

整理暴露物–靶点–结局表并出分层图；不改写 I₁/C。

5. 参数与取值原因

结局词表为课题冻结；不引入完整 TCMToxDB 主线参数。

6. 输入与输出

输入：暴露物与线索表。输出：毒性分层表/图。停机：本支线失败不阻塞 03–08，但须在报告注明。

7. 结果数据与图片怎么读

读分层表与图；方法版不强制拼图。验收：结局词表与排除名单可追溯。

8. 解读边界

只写毒性线索，不用「减毒/拮抗」作主结论。

04 机制层

1. 为何采用这一分析

在已定义的 C 上给出 PPI/模块/富集/五层网络语境，供代谢物分层与对接配对阅读。不在此步重算 C。

2. 数据来源

来自分析：上游 03 的 C 基因列表。

数据库：STRING（Homo sapiens）互作边。

为何用 STRING：与网药交付流水线一致，可用 combined score 复现过滤；不用把低置信边画进主图。

原始：C 表（03 处理后）。处理后：04_机制层_PPI富集/结果文件/数据文件/机制层/。

3. 筛选标准

combined score ≥ 0.9（课题偏严锁定）。枢纽用 MCC-like=Degree×局部三角（非官方 cytoHubba 分数）。GO/KEGG 背景为 D 映射后的 Entrez。这样洗是为了主图只保留高置信互作，并与疾病宇宙集对齐。

4. 数据处理与函数

读 C→拉 STRING 边→过滤→MCC-like 排序→MCODE 兼容模块→GO/KEGG→五层网络摘要图与 CSV。

5. 参数与取值原因

score≥0.9 课题锁定；MCODE 参数见阶段报告。富集显著性阈值按阶段脚本（BH）。

6. 输入与输出

输入：C。输出：PPI/枢纽/GO/KEGG/配对与五层网络文件。停机：C<背景要求时按脚本跳过富集并记录。

7. 结果数据与图片怎么读

验收：PPI 边表 + GO/KEGG 显著表存在。

8. 解读边界

共同调控候选语境；非复方特异通路定位。

06 分子对接

1. 为何采用这一分析

科学目的：在同一过筛靶点宇宙 C* 上读出「活性成分 × 靶点」的结合选择性格局——哪些靶点被多种成分共同强结合，哪些只认特定成分。为何多对多而非一配体一靶点：单对读不出选择性，3×4 全组合才能并列比较同一配体跨靶点与同一靶点跨配体。为何不用旧手挑对：旧表未先过网毒硬过滤、成分 Degree 未限制在剔除后的 C*，与论文范式不一致。更早的 C* 双轨批次（成分轨 + 代谢物轨，一配体一靶点）保留归档作历史引用（表路径见 §2），不再作为本轮主口径。

2. 数据来源

数据库：PubChem（配体）；RCSB PDB（受体）；STRING human 边（score≥0.9）；CTD（有害小分子暴露物策展互作）。

来自分析：01 网药 F、03 代谢 M、疾病 D；02 网毒有害小分子清单。

为何这些结构：四个受体均有可用 UniProt+PDB——PCNA P12004/1U7B、DNMT1 P26358/3EPZ、ESR2 Q92731/1L2J、FOS P01100/1A02；定心按决策树（见 §3），有共晶小分子优先共晶包盒，否则 AutoSite/P2Rank/annotated_site，并在表中注明 site 与 center_source。

原始：06_分子对接/数据文件/原始数据/RCSB与PubChem_对接结构工作区/ 与上游模块表。处理后：06_分子对接/结果文件/数据文件/筛选执行_SelectionRun/；对接 06_分子对接/结果文件/数据文件/对接/——本轮多对多 3×4 产物 多对多3x4_对接汇总.csv（13 行=12 对；luteolin–PCNA 为双行：新跑 adgpu 主值 + vina_legacy 历史行，engine 列区分，含 center_source）、多对多3x4_对接全表.csv（39 行种子级：12 对 × 3 种子 + luteolin–PCNA 历史 3 行）、summary_adgpu_多对多3x4.csv、矩阵_结合能_多对多3x4.csv；热图 06_分子对接/结果文件/图片文件/矩阵_结合能热图_多对多3x4_DockingAffinityHeatmap3x4.png/.svg；PyMOL 三视图 06_分子对接/序号文件夹/01–12/（big/surface/detail .pse 于任务根，图片/big-N.png、surface-N.png、detail-N.png、result_N.png 已出齐（2026-10-15）；任务 04 复用对沿用旧批次定稿图，任务 05 为 2026-10-15 补齐新跑（luteolin–PCNA，与任务 01/09 同源 p2rank 口径），同步出齐图件，见 待办_detail手调与result拼图_提示.md；result 拼图图册清单见论文版对接节）。历史双轨批次表 成分对接汇总.csv、代谢物对接汇总.csv 等留在同目录；代谢物批次（色氨酸–MMP9、腺苷–ADA 等）表在 交付文件/06_分子对接/结果文件/数据文件/对接/（对接汇总.csv、对接全表.csv），同数见 06_分子对接/结果文件/报告文件/报告_Phase5_分子对接.md。

标准 SSOT：06_分子对接/研究思路与标准_Paradigm/筛选标准_SelectionCriteria.md（技能夹同步副本）。

3. 筛选标准

多对多取样（本轮主口径）：C* 派生沿用：C=F∩M∩D（|C|=78）→ 网毒硬过滤（|ToxHard|=27）→ C*（|C*|=51）→ STRING（score≥0.9）Top 8 靶点（PCNA、DNMT1、ESR2、FOS、PPARG、EZH2、TOP1、GAPDH）；硬过滤先去明确有害暴露物相关靶点，避免把风险轴当治疗主轴，Degree/PPI 在剔除后重算，LPS/H₂S 不整片删 C 也不作对接配体。本轮在 Top 8 中取 PCNA/DNMT1/ESR2/FOS 四受体，与 quercetin、luteolin、kaempferol 三配体做全组合 3×4=12 对；每对种子 1/7/42 独立运行取均值；通过判据：三种子均值 ≤ −5.0 kcal/mol 并记 pass_rate。为何全组合：选择性格局（共同强靶 vs 选择性识别）只有同批并列比较才能读出。

定心决策树（FROZEN，每任务强制登记 center_source）：有可用共晶小分子 → cocrystal_meeko/cocrystal；无共晶 → AutoSite；质控 FAIL → P2Rank → 文献/annotated_site/manual → FAIL。禁止整链 COM、全 HETATM 平均、固定边长 22、未校验照抄库表。本轮实际：cocrystal_meeko 6 对（DNMT1 3EPZ BGC:A:702、ESR2 1L2J ETC:A:600，meeko_enveloping）、p2rank 3 对（PCNA 1U7B rank=2，rg_4_5x；含任务 05 补齐跑，与任务 01/09 同盒同地图）、annotated_site 2 对（FOS 1A02 参考位点=DNA 链 A/B 界面，受体按 FROZEN 剔除核酸，rg_4_5x）；11 对盒质控均 box_qc=PASS。

engine 区分与复用对：11 对新跑走 AutoDock-GPU（AD4、--nrun 20，AutoGrid 出 .maps.fld）；1 对复用旧结果——quercetin–FOS（任务 04）为 Vina 几何中心盲对接（engine=vina_legacy、center_source=legacy_blind_geometric_center、fixed22_legacy；废止法，仅作历史引用），不重跑。luteolin–PCNA（任务 05）原为复用旧值（−4.60±0.53 kcal/mol，vina_legacy），2026-10-15 经用户确认以与任务 01/09 完全同源口径（p2rank rank2 PIP 沟、同盒同地图）补齐新跑 AutoDock-GPU（−5.31±0.00 kcal/mol）；旧值在 多对多3x4_对接全表/汇总.csv 保留为历史行（engine=vina_legacy），矩阵格与报告主值用新 AD-GPU。汇总表 engine 列区分 vina_legacy 与 adgpu，AD-GPU 与 Vina 分表登记（summary_adgpu ≠ summary_vina）。历史 C* 双轨批次（一配体一靶点，成分轨 8 对 + 代谢物轨 8 对）的筛选总序与逐对数字见 成分对接汇总.csv/代谢物对接汇总.csv，本轮不复述。

对接通过：三种子均值 ≤ −5.0 kcal/mol 且建议 pass_rate=1。旧硬编码对接对剔除并归档至 .../对接/_归档_旧对接_*。

5. 参数与取值原因

6. 输入与输出

输入：C + GEO 矩阵。输出：验证表与图。停机：映射失败基因过多则只报映射率、不宣称 AUC。

7. 结果数据与图片怎么读
