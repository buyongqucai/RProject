# 虚拟敲除方法论（可复用 SSOT）

> **存放（唯一）：** 本技能 `文档_docs/虚拟敲除方法论_VkoMethodology.md`。  
> 课题目录、桌面交付夹（含琪乐无穷等）**只放该课题的实例计划与结果**，不另写第二份方法论。  
> **入口：** 技能说明只留指针。  
> **不做的事：** 不预设多种算法的排列组合或相互验证。对比是**另开的可选任务**，不是每条算法计划的默认章节。

---

## 1. 一条研究 = 一个引擎实例

| 概念 | 含义 |
|------|------|
| **课题实例** | 物种 + 组织 + 生物学状态 + 敲除基因 + 细胞宇宙 + 数据集 |
| **引擎** | 一种虚拟敲除算法及其官方软件（如 scTenifoldKnk、GenKI） |
| **实例计划** | 把「课题实例 × 单一引擎」写成一份可执行计划（参数、阶段、验收、声称语言） |
| **对比任务** | 仅当用户**明确要求**时，读取两份已完成实例的产物做重叠/通路对照；单独开计划，不写进任一引擎计划的必做项 |

同一课题可以先后或并行存在多份实例计划（引擎 A、引擎 B、引擎 C）。它们**共享数据切片说明**，**不共享结果表、不互相改写结论**。

---

## 2. 新课题怎么开工（固定顺序）

1. 填接诊确认表（[`接诊与确认表单_IntakeConfirmForm.md`](接诊与确认表单_IntakeConfirmForm.md)）：`method` **只填本实例要用的一个引擎**。  
2. Phase1：数据可行性（登录号、亚群/细胞宇宙、靶基因检出）。  
3. 从方法登记（[`方法默认与信源登记_MethodDefaultsRegistry.md`](方法默认与信源登记_MethodDefaultsRegistry.md)）抄该引擎的默认参数与文献；与数据集冲突处披露。  
4. 按本文 §4 模板写 **一份** 实例计划，放到**该课题自己的目录**（交付夹或桌面课题夹）。不要把实例计划写回本方法论。  
5. 跑分析 → 出图（叠加 VizStandards + DeliveryStandards；Knk 主线图序见出图图册；其它引擎用自己的图种，不借用别的引擎列名）。  
6. 解读只写 **计算预测**，禁止写成真实 KO DEG。

换主题时：复制 §4 空表，改字段；方法论与技能入口不动。

## 3. 引擎卡片（可追加，互不绑定）

新增算法时只在方法登记加一行卡片（文献、软件、输入、输出语义、硬件、不适用），并允许单独写实例计划。**不要**在卡片里写「必须与某某对照」。

| 引擎 ID | 文献 | 输出语义（不可混名） | 典型硬件 |
|---------|------|----------------------|----------|
| `scTenifoldKnk` | Osorio et al., *Patterns* 2022, [10.1016/j.patter.2022.100434](https://doi.org/10.1016/j.patter.2022.100434) | DR / distance / `p.adj` | CPU；加速另见该实例的优化节 |
| `GenKI` | Yang et al., *NAR* 2023, [10.1093/nar/gkad450](https://doi.org/10.1093/nar/gkad450) | 潜空间距离（如 KL）+ 排列检验排序 | CPU 建网 + GPU 训练 |
| `CellOracle` | 用户点名时再启用 | 按该文/该包字段 | 见当时计划 |
| regulon 逆转 | 仅 master TF + 已有 DEG | rescued DEG 计数 | 非转录因子不适用 |

## 4. 实例计划模板（每个引擎一份）

```markdown
# <课题短名> — <引擎ID> 实例计划

## 问题
（一句话：在何种细胞状态下，虚拟敲除某基因，要预测什么）

## 数据
登录号 / 路径；细胞筛选；基因过滤；必须保留的靶基因

## 引擎与参数
软件版本；关键参数及来源（H/M）；与官方默认的偏离及原因

## 阶段
1. 准备矩阵/对象
2. 运行
3. 显著性与富集（本引擎自己的规则）
4. 出图与 STATUS

## 验收
可复现命令或脚本路径；完成标志文件

## 声称
计算预测；禁止事项（不写成湿实验 KO；不借用其它引擎的列名）

## 优化（可选，仅本引擎）
加速/GPU/断点：必须先与本引擎参考实现做数值对齐，再决定能否替换主结果

## 本计划不包含
对其它算法的对照、共识或组合验证（除非用户另开对比任务）
```

## 5. 对比任务（可选，默认关闭）

仅当用户说出需要（例如「看 Knk 与 GenKI 是否一致」）时新建第三份短计划，输入是**已经跑完**的两份产物。  
未要求时：各实例独立成文、独立投稿段落，不预写 Jaccard/共识章节。

---

## 6. 优化原则（对任一引擎通用）

- 官方/参考实现的主结果与加速实现分目录。  
- 加速版升格为主结果的条件：同一输入、固定种子下，该引擎定义的主统计量对齐（写入该实例计划，不写进本方法论的具体阈值堆砌）。  
- 无 CUDA 的包可以另做加速原型；未对齐前不得改称「官方结果」。  
- 不中断用户已在跑的正式任务，除非用户明确要求停止。  
- 两个引擎同时在跑时，后启动的那个要限制自己的 CPU 线程，并至少留出一部分逻辑核给操作系统的日常操作。不提高已在跑的引擎的 worker 数。不要在已经有重计算任务的机器上再启动另一个引擎。
- 单独一台机器只跑一个引擎时，开跑前先探测这台机器的 CPU、内存和显卡，按比例预留给操作系统，其余分给算法。比例写在该引擎的执行入口里，不把某一台机器的线程数或显存写进计划。显卡正在输出桌面时才预留显存。

## 7. 引擎实施要点（换课题时照抄，参数以方法登记为准）

### scTenifoldKnk

1. 输入：原始 counts（基因×细胞）；`qc=TRUE` 时不要预先归一化。  
2. 流程：QC → CPM → `makeNetworks`（PC 回归，`nNet` 张网）→ CP 张量分解 → 靶基因出边置零 → 流形对齐 → DR（distance / `p.adj`）。  
3. 基因过滤：优先高表达，必须保留敲除基因；不单用 HVG（作者 Issue #33）。  
4. 图：出图图册；显著集规则以方法登记「画法与筛选」为准（FDR 与 STRING 分开）。  
5. 加速：官方 Rcpp `pcNet` 在 `useRcpp=TRUE` 时忽略 `nCores`（基因环串行）。加速实现与参考实现分目录；未做数值对齐不得称为官方结果。包本身无 CUDA。

### GenKI

1. 输入：WT 的 `AnnData`；目标基因必须在矩阵中。  
2. 流程：建/缓存 GRN → 训练 VGAE → WT 与虚拟 KO 的潜变量距离（如 KL）→ 排列检验后排序。  
3. 参数是否变动，按 Yang et al., *NAR* 2023 的 Ray Tune 协议，写在该课题实例计划。不把软件 README 的示例学习率当作跨数据集标准。响应基因用原文的排列规则，不套用 scTenifoldKnk 的 FDR。  
4. 硬件：VGAE 训练用 GPU。开跑前运行该课题的资源探测，由它按当前机器分配线程、搜索并发、内存和显存。换机器就重新探测，不手写核数。  
5. 列名与图注用 GenKI 自己的字段，不写成 Knk 的 DR 表。

在方法登记加一行卡片，并在本节追加不超过半页的实施要点。不在卡片或要点里绑定其它引擎。
