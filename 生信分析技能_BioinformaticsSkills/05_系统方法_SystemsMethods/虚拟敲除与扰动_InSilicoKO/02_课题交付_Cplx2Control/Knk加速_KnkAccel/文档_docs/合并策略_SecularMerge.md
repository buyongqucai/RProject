# secular 合并

记录时间：2026-10-02。1 个 BLAS 线程。评估量是 `特征值个数 × 基因数 × nComp × 300`，300 是迭代上限。调用者指定 `device="gpu"` 且 `merge="auto"` 时，这三个尺寸都选择合并成一个双精度 CUDA 核。`device="cpu"` 仍走原来的循环。评估不会把 GPU 请求改回 CPU。

每个进程第一次编译这个核大约多 0.4 秒。下面的秒数是编译之后的稳定计时。

## 和未合并的 GPU 循环比

`q=0`，不做缩放。最大绝对差是两条 GPU 路径彼此的差。

| 矩阵 | 评估量 | 未合并 | 合并 | 最大绝对差 |
|---|---:|---:|---:|---:|
| 40×30 | 1.08e6 | 0.180 秒 | 0.004 秒 | 9.714e-17 |
| 800×200 | 1.44e8 | 0.248 秒 | 0.030 秒 | 1.648e-17 |
| 8000×425 | 3.06e9 | 0.583 秒 | 0.351 秒 | 4.554e-18 |

## 和 CPU、仓库比

`q=0.9`。CPU 是未合并的循环。

| 矩阵 | CPU | 合并后的 GPU | 最大绝对差 |
|---|---:|---:|---:|
| 40×30 | 0.032 秒 | 稳定 0.004 秒；新进程第一次含编译约 0.45 秒 | 对 CPU 4.219e-15 |
| 800×200 | 0.133 秒 | 0.062 秒 | 对 CPU 4.619e-14 |
| 8000×425 | 6.141 秒 | 2.118 秒 | 对 CPU 2.331e-14 |
| 仓库那张 40×30 | | | 对 `pcNet.R` 1.532e-14 |

800 基因上，合并之前 GPU 比 CPU 慢。合并之后 GPU 更快。8000 基因上 GPU 仍然更快，整张网的 2.118 秒里包含分位数。

## 8000×425 的时间落在哪

合并后的一张网，`q=0.9`。1 个 BLAS 线程。

| 步骤 | 秒 | 在哪 |
|---|---:|---|
| 标准化 | 0.026 | GPU |
| 425×425 特征分解 | 0.024 | GPU |
| secular 核 | 0.053 | GPU |
| 系数矩阵乘完并拷回内存 | 0.255 | GPU 乘法，然后拷贝 |
| 分位数 | 1.418 | CPU |

同一张显卡上再放一路 secular：一个核 0.051 秒，两个核串行 0.102 秒，两条 CUDA 流同时跑 0.090 秒。双精度单元被一个核占满，建网并发没有再快出一截。MSVC 只编译主机端的启动代码，设备端仍然是现在这个 sm_89 的双精度核，换它不会动这 1.418 秒。
