# 这一轮优化记录

记录时间：2026-10-03。机器是 RTX 4080 SUPER 16 GB。写前面各节时正式任务仍在跑，所以那些计时固定 1 个 BLAS 线程，没有写 Formal 的结果目录，也没有停那个进程。NF1 于 12:18 结束，五亚群旧 Formal 已留档。公布用的数仍是双精度。1.4 和 1.4.3 不是同一个公式：1.4 是每个基因一次留一回归的截断 SVD，1.4.3 是 Gram 矩阵加 secular 方程。两边各自对上自己的定义。和正式表对齐的是 `nDecimal=3` 之后的 distance、p.adj 和 WT，不是说每个原始系数都逐位相同。

## 改了什么

1. 1.4 在样本和基因都不超过 40、且都大于 `nComp`、`nComp` 不超过 8 时，标准化、Jacobi、放回系数、按最大绝对值缩放、type 7 分位、对角线置零，合成一次启动。更大的矩阵仍是每个基因一次 cuSOLVER `gesvd`。
2. 1.4 的长循环不再每个基因都把 GPU 同步回主机。进度回调改成每 100 个基因同步一次，最后再同步一次。缩放用的最大绝对值留在显卡上除，不再为了读一个标量同步。
3. NVRTC 编出来的机器码按显卡架构和源码摘要存到本机 `%LOCALAPPDATA%\knk_accel\cubin`。同一进程里第二次调用直接用已加载的函数。
4. 短边不超过 128 的 1.4 CPU 用 LAPACK `gesdd`，更长的仍用迭代截断。`device="auto"`：1.4 用 CPU，1.4.3 在有 CUDA 时用 GPU。显式写出 `cpu` 或 `gpu` 时不改道。没有 CUDA 时 `gpu` 报错。
5. 检查点建网不再让「下一张网的 SVD」和「上一张网的显存拷贝」叠在一起。一张网算完、拷回主机、释放缓存，再算下一张。环境变量 `KNK_GENE_STATUS` 若指向一个文件，每 100 个基因追加一行基因序号；不设就没有任何额外写盘。

## 哪一项没有变快

40×40 以内的 1.4 GPU 并没有因为合成一次启动而变快。24×18 热身后 0.0267 秒，改之前约 0.026 秒。40×30 热身后 0.1277 秒，改之前约 0.115 秒。对 CPU 的最大绝对差分别是 1.067e-13 和 1.421e-14，置零位置差是 0。同一档 CPU `gesdd` 在 24×18 上是 0.001 秒。核里每个线程都有大约 25 KB 的局部数组，占用率上不去。所以 1.4 的 `auto` 继续留在 CPU。不要把这一项说成加速。

缓存机器码也没有去掉新进程的热身。PTX 缓存时，新进程第一次 1.4.3 GPU 调用 0.420 秒，第二个进程 0.386 秒。改成 cubin 之后，CUDA 已经初始化的进程里，加载 secular 核仍要 0.112 秒，和加载 PTX 的 0.105 秒同一档。拆开看：`torch.linalg.eigh` 第一次 0.054 秒、第二次 0.0008 秒；核加载之后的第一张 24×18 网仍要 0.203 秒，第二张 0.0031 秒。多出来的是这个进程第一次碰到的 PyTorch 核，不是 NVRTC 又编了一遍。一张 8000 基因的网本身要 1.4 秒左右，这 0.1 秒只出现在第一张。

1.4 在 cLTMR 上把同步从每个基因改成每 100 个基因，10 张网的合计没有下降。上一轮 GPU 是 8167 秒。这一轮 10 张网的计时加起来是 8777 秒。后 5 张关掉重叠拷贝之后，单张是 868 到 877 秒，上一轮单张大约 802 到 876 秒。时间在 `gesvd` 本身。8000 个约 425×7999 的双精度分解，这张卡没有双精度 Tensor Core。

## 用户确认：稀疏 GPU 张量

2026-10-03 确认保留现在这条稀疏 GPU CP。不改回稠密数组，也不改成 R 的 BLAS 相加顺序，不多跑官方停机点之后的轮次。

cLTMR 上，残差停在 885.808，张量范数约 979。大约九成范数留在残差里，这是 K=3 对十张网的拟合，官方 CP 用的也是这个秩。停机看的是残差还变不变。第 10 轮比值 1.221e-5，是容差 1e-5 的 1.22 倍，没有停。第 11 轮比值 5.797e-6，是容差的 0.58 倍，在这里停。这个空隙比双精度舍入大很多个数量级。收到 3 位小数之前，离 `x.xxx5` 最近的一格差 1.826e-13。清对角线并转置之后，对正式 WT 的最大绝对差是 0。

同尺寸一次乘法，稀疏约 0.055 秒，稠密约 0.072 秒，最大绝对差 2.70e-13。稠密 GPU 走的是 cuBLAS 的顺序，不是 R 的顺序。官方 R 这一步大约 190 秒，主要耗在分配和抄写两块 5 GB 数组。

非零项的相加顺序仍然不同。稀疏核按一行里的非零元加，R 的稠密 BLAS 按分块加。双精度里这是末位差别。它会变成看得见的结果，只有两种边界：残差变化贴着 1e-5，多做或少做一整轮；或者缩放后的数贴着 `x.xxx5`，3 位小数进位差 0.001。零本身不会单独造成这种跳跃。

2026-10-03 再确认：1.4 的 GPU 分解保持每个基因一次留一 SVD，不改成 1.4.3 的一次 Gram 加 secular。能把一张网从大约 878 秒收到大约 15 秒的，就是这一次改道。精确算术里两边是同一次留一回归，60×40 上差 7.205e-14，两条路径仍然分开。张量不看建网公式。`q=0.9` 之后的网交给同一个稀疏 GPU CP。1.4 昨晚的后半段仍是官方稠密张量，175.540 秒；稀疏函数还没有在这十张 1.4 的网上跑过。

## 临时加计算资源

尚未改代码。现在的并发只在一整批开始时算一次。GPU 路径固定一个进程、一次一张网；已有至少 4 个 Rscript 时，CPU 路径固定 1 个进程。

一张网写完之后，下一张开始前可以再看空闲核、空闲内存和空闲显存。检查点已经按网跳过写完的文件，所以中途停掉、资源空出来再开，下一张能用新的计划。正在进行的一次 `gesvd` 或一张 1.4.3 的 secular 核不能中途加核。这张卡上预热后两路双精度 `gesvd` 没有加速，16 GB 显存叠两张 8000 基因的网会再次撑满。1.4.3 的建网和稀疏 CP 已经是几秒，多出来的 CPU 核用不上。没有第二块显卡。正在跑的 Formal 是另一个 R 进程，GPU 代码不能把核塞进那个进程。

能用上临时多出来的核的，是 CPU 路径上下一张网的基因并行。GPU 上的 1.4 分解和 1.4.3 建网不会因此变快。
