# scTenifoldNet / scTenifoldKnk 优化计划

这份计划准备交给开源说明。数学定义保持上游包：留一主成分回归、只留 3 个最大奇异方向、分位数删边、CP 张量、出边置零、流形对齐、`dRegulation`。优化只改计算路径和数据放在哪里。默认结果在对齐通过之前不替换。

上游是 [scTenifoldNet 1.4](https://github.com/cailab-tamu/scTenifoldNet) 和 [scTenifoldKnk 1.1](https://github.com/cailab-tamu/scTenifoldKnk)，许可证都是 GPL (>= 2)。派生代码保持同一许可证，并注明原作者。GPU 路径作为可选后端，没有 CUDA 的用户仍走原来的 CPU。

准确性优先于速度。全程使用双精度，舍入规则与 CPU 相同（四舍五入到最近，中间取偶数）。不使用单精度、半精度或 Tensor Core 格式作为对外结果。

## 直接 SVD 和 Gram 差在哪里

每个基因的设计矩阵记为 A。cLTMR 里它大约是 425 行（抽到的细胞）乘 7999 列（其余基因）。要的是 A 上变化最大的 3 个方向，也就是最大的 3 个奇异向量。原包的 `svd_econ` 和 CPU 截断路径都是直接分解 A。

Gram 先算 G = A Aᵀ，得到 425×425，再求 G 的特征向量。无限精度下，这些特征向量和 A 的奇异向量是同一组。双精度下不是。

条件数是最大奇异值除以你关心的那个奇异值。若 A 的这个比值是 10⁴，G 的特征值是奇异值的平方，比值变成 10⁸。双精度大约只能分辨 10¹⁶ 倍的大小。比值被平方之后，较弱的那个方向会先被舍入淹没。直接分解 A 时，同一个方向还在。

所以 Gram 不是「另一种舍入」，而是先把问题变难再求解。抽查的 10 个基因只差 1.132e-16，是因为这 10 个的前 3 个方向还不够弱。不能据此认为 8000 个基因里没有更弱的。

误差不会因为张量多迭代几轮就无限变大。它停在机器精度乘这一步的条件数附近。Gram 把条件数平方，是放大会真正发生的地方。

## 设备由使用者选

原因：按基因数自动切到 GPU，使用者无法在小矩阵上指定显卡，也无法在大矩阵上强制只用 CPU。当前代码 `use_gpu_for` 在基因数不少于 1000 且细胞数不少于 200 时自动用 GPU。这是按规模选择，将改掉。

没改什么：这一决定本身还不改公式。改完之后，不写设备就保持原包 CPU，不偷偷用显卡。

做法：参数只接受调用者写明的 `cpu` 或 `gpu`。一次运行只走一边。没有 CUDA 却选了 `gpu` 时直接报错，不静默退回。

效果：尚未改代码。生效后要在记录里写一次：同一矩阵上两种选择的最大绝对差和墙钟。

## 取消：同一流程里 CPU 和 GPU 一起算

原因：曾考虑把一张网的基因编号切开，一段用 CPU 直接截断 SVD，另一段用 GPU 做同一个 SVD，写进不同的系数行。公式可以保持一致，但调度、缓冲和线程数要额外设计。当前没有这块的实现经验，先不放进这一版。

没改什么：系数公式、抽样、分位数类型都没因为这条思路改过。代码里也没有 `both`。

这一版的做法：调用者选 `cpu` 就整张网在 CPU 上做直接截断 SVD；选 `gpu` 就整张网在 GPU 上做。算完再在同一边把系数交给后面的删边。不把一张网拆给两台设备，也不让 GPU 算下一张时 CPU 去写上一张。那种重叠属于调度，等这一版对齐之后再单独立项。

效果：没有测过共同执行。不记录速度收益，因为没有这条路径。

## 已经做过的

### 截断 SVD 代替完整 SVD

原因：`pcNetCoreRcpp` 对每个基因做完整经济 SVD，再只留 3 个分量。正式 cLTMR（8000 基因、约 425 个细胞、10 张网并行）这一步超过 6 小时。

没改：留一回归和「只留最大的 3 个方向」。

效果：1200 基因 × 150 细胞，4 进程系数对 Rcpp 的最大差 7.095e-16，1 进程 11.2 秒，4 进程 4.1 秒，官方 1 线程 77.3 秒。400 基因 × 200 细胞、另一套种子，系数差 1.734e-15。没有在 8000 基因上对过 Rcpp。

### 按网落盘

原因：中断后只需重算未完成的网。细胞下标在 SVD 前写一次，网和完成标记在算完后写。

效果：续跑不会把第 3 张抽成第 1 张。进度文件不按基因写盘。官方包本身不逐张落盘，开源补丁里这是额外能力，不改变抽样。

### GPU 上的 Gram 路径（不作为默认）

原因：为了少算，把 425×425 的 Gram 矩阵拿去求特征值。无限精度下与直接 SVD 相同。双精度下 Gram 会把条件数平方，病态基因会比直接 SVD 更偏离设计矩阵的真实奇异向量。

效果：cLTMR 抽查 10 个基因，对 CPU 直接截断 SVD 的最大差 1.132e-16；一张网约 15 秒。这 10 个基因没有显示放大。8000 个基因尚未逐一对比。按准确性优先，这条路径不进入开源默认。

### 后半段的 GPU 试探

原因：看张量乘法和流形对齐上 GPU 能快多少。不是为了把这两步排除出这一版。

效果：合成矩阵，边长 5000、40 轮，CPU 1 线程 199.130 秒，GPU 双精度 3.748 秒。10000 阶求 4 个最小特征值，CPU 26.200 秒，GPU 3.915 秒。8000 阶一行置零和二维距离，GPU 没有更快。数据不是真实网络。流形那次用的是 `lobpcg`，不是官方的 `RSpectra::eigs`。乘法类步骤保留官方迭代，只换执行设备；置零和距离留在 CPU。

## 这一版运行时谁做什么

设备按已经做过的测试分工。调用者选 `gpu` 时，下面标 GPU 的步骤整步在显卡上做完；选 `cpu` 时这些步骤留在 CPU。一次只走一边，不把同一步拆给两台设备。

| 顺序 | 步骤 | 选 GPU 时谁做 | 依据 |
|------|------|----------------|------|
| 1 | `scQC`、`cpmNormalization` | CPU | 这一版不改。没有测出适合搬上显卡 |
| 2 | 10 张网：抽样下标在 CPU，标准化、直接截断 SVD、系数、第 7 型分位数 | GPU | 正式规模上这是数小时的那一步 |
| 3 | `cpDecomposition` 里每一轮的矩阵乘法 | GPU | 边长 5000、40 轮：199.130 秒对 3.748 秒。迭代公式仍是官方 CP |
| 4 | `strictDirection`、对角线置 0、转置、敲除基因那一行置 0 | 矩阵已在显存就留在 GPU 上做完 | 单独把 8000 阶搬上显卡再置零，GPU 更慢。为置零专程搬运不划算 |
| 5 | `manifoldAlignment` 里对 W 的矩阵向量乘，求 4 个最小特征值 | GPU | 10000 阶：26.200 秒对 3.915 秒。问题仍是官方那个特征问题。`lobpcg` 只是计时探针，不能直接换成对外结果 |
| 6 | `dRegulation` 的距离和校正 p 值 | CPU | 8000 个二维距离：CPU 0.000125 秒，GPU 0.000148 秒 |

选 `cpu` 时没有显存搬运。计数从硬盘进主机内存；按网落盘从主机内存回硬盘。

选 `gpu` 时的搬运：

1. 质控和 CPM 之后的计数，主机内存整块上传到显存，只一次。cLTMR 大约 27 MB。
2. 每张网的细胞下标在 CPU 抽好，只把这段下标送到显卡。显卡用这些细胞单独标准化。
3. 直接截断 SVD、系数、删边在显存里做完。稀疏网拷回主机内存，供落盘。显存里留下这张网，供后面的张量使用，不把 10 张稠密网先卸下来再传回去。稠密系数大约 0.5 GB，不按基因往返。
4. 10 张网在显存里按顺序进入 CP。上一张拷回结束之前，不覆盖还要落盘的那块输出。
5. CP、方向整理和敲除行置零都在显存里做完。这里不再为了置零把大约 5.1 GB 的张量卸回主机。
6. 流形对齐的 W 在显存里形成并做矩阵向量乘。W 大约 2.0 GB，不先在主机内存里建好再上传。
7. 只把低维坐标从显存拷回主机内存，在 CPU 上做距离和 `dRegulation`。

当前代码还没有改成这样。大矩阵的建网仍会自动走 Gram，张量和流形对齐还没有接到显卡上。

## 收窄记录

上一张流程图把后半段五步都画成官方 CPU，并写「显卡不再参与」。那是把「先和官方函数对上、不改数学定义」写成了「这些步骤不上 GPU」。测试里已经更快、并且你要求移植的，是建网、张量乘法和流形对齐里的矩阵向量乘。置零和距离的单独计时没有更快，所以距离留在 CPU；置零不单独再搬一次。

## 接下来按这个顺序做

### 1. 默认改回直接截断 SVD

原因：更贴切的是设计矩阵本身的前 3 个奇异向量，不是 Gram 的特征向量。原包的 `svd_econ` 也是直接分解。

做法：调用者选定 `cpu` 或 `gpu` 之后，整张网在这一边对设计矩阵做双精度直接截断 SVD，只留 3 个最大奇异方向，再用原来的系数公式。不按矩阵大小自动选设备，也不在这一步把基因分给另一台设备。Gram 不作为默认。显存复用、整块上传不在这一步混进去。

对照：同一标准化矩阵上，GPU 直接 SVD 对 CPU 直接 SVD；再对 `pcNetCoreRcpp`。先用已有的小矩阵和中等矩阵。8000 基因等 Formal 不再占满核之后，用 1 个线程做，不新开 20 线程。

通过：系数最大绝对差 < 1e-5。记录最大差、中位数、最差的基因编号。差若只出现在少数基因，把这些基因的奇异值谱写进记录，说明是病态而不是搬错了缓冲。

### 2. 搬运只改位置

原因：整块搬运是零点几秒，按基因来回搬才会盖过计算。搬运不改变双精度的值。

做法，且每条都保持上一步的直接 SVD。整张网只在调用者选定的那一台设备上算完，再进入下一张：

- 原始计数上传一次。每张网仍只用自己的细胞下标，在显卡上单独标准化。禁止先按全部细胞标准化再抽样。
- 10 张网按顺序复用同一块显存。上一张的系数拷回结束之前，不开始覆盖那块输出。
- 分位数仍用 R 的第 7 型。选了 GPU 就在显卡上删边，只拷回稀疏网；选了 CPU 就在 CPU 上删边。
- 两块缓冲交替、第二条流提前拷回、GPU 算下一张时 CPU 写上一张，都留到调度优化，不进这一版。

对照：稀疏网还原成稠密网后，与第 1 步的稠密结果比最大绝对差，并比非零边集合。边集合必须一致。

### 3. 张量和流形对齐换设备，不换公式

原因：这两步的大乘法在测试里更快。边长 5000、40 轮的 CP 乘法是 199.130 秒对 3.748 秒；10000 阶、4 个最小特征值是 26.200 秒对 3.915 秒。置零和距离没有更快。

做法：建网的直接 SVD 对齐通过之后，GPU 路径继续用同一套网做官方 CP 的矩阵乘法，再做 W 的矩阵向量乘。迭代停止条件、K=3、4 个最小特征值保持官方定义。`lobpcg` 不作为对外求解器，除非它和 `RSpectra::eigs` 的结果先对上。距离和校正 p 值在 CPU。对照仍是官方函数的 `distance` 最大差，以及 `p.adj < 0.05` 集合的对称差。

这一步和建网的直接 SVD 分开记录。对不上时，先看是乘法结果不同，还是特征求解器不同。

### 4. 开源补丁的形状

原因：CRAN 用户多数没有这张显卡。改默认实现会让旧结果对不上。

做法：

- 参数里由调用者选择 `cpu` 或 `gpu`。默认仍是 `original`，不按规模自动改道。一次运行只使用一边。
- GPU 放在可选包或可选编译开关里，不进强制依赖。同一时间只允许一个进程占用这张显卡。
- 说明文件写清：双精度、直接 SVD、与 Rcpp 的最大差、测过的矩阵尺寸、没有测过 8000 基因时就不要写已经替换正式结果。
- 提交说明附上每一步的记录表。许可证保持 GPL (>= 2)。

## 落盘契约

建网中断后能否续跑，认的是这三件套，不是显存里的矩阵。进程一停，显存就空了。下次启动只看输出目录。

| 文件 | 何时写 | 里面有什么 |
|------|--------|------------|
| `net_XX_indices.npy` | 这一张网的 SVD 之前，只写一次 | `int32` 细胞下标。有放回抽样的结果 |
| `net_XX.npz` | 稀疏网算完，原子替换 | CSR 的 `data`、`indices`、`indptr`、`shape`；同一份 `cell_indices`；`genes`；`n_comp`；`q` |
| `net_XX.done` | `npz` 替换成功之后 | 内容只有 `ok`。它是完成标记，不是第二份矩阵 |

`XX` 是至少两位的网号，第 3 张是 `net_03`。半截文件只用 `.partial`，扫描时删除。不按基因写系数，不写每次 SVD 的 U、s、V。

下次启动的识别：

| 磁盘上有什么 | 动作 |
|--------------|------|
| `.done` 和非空 `npz` 都在，且 `genes`、`n_comp`、`q` 与本次调用一致 | 跳过。不重新抽样，不重算这张网 |
| 只有非空的下标文件 | 沿用这份下标重算。不抽一套新细胞 |
| 只有 `.done`、`npz` 是空的、或参数对不上 | 去掉失效的 `.done`，按下标或新算处理 |
| 三件套都没有 | 新抽样，先写下标再算 |

当前代码在扫描时核对 `genes`、`n_comp`、`q`。三项一致才跳过。不一致就去掉 `.done`，若下标还在就沿用下标重算。小测：同一张已完成的网改用 `q=0.95` 再扫描，完成标记被去掉，动作是沿用下标。文件格式没有改。

张量和流形对齐还没有读这些 `npz`。字段足够重建稀疏网。改造时从磁盘读回，再按调用者的选择放上 CPU 或 GPU。不能假设上次的显存还在。

正式 R 脚本的续跑是另一个单位：一个亚群的 RDS 和 CSV 都在，才跳过整个亚群。它认不出 `net_XX.npz`，也没有建网中途的百分比续跑。正在跑的 Formal 因此做不到「断在第 23 张网、下次跳过前 22 张」。

加速代码里，续跑单位是一张已经写完的网，不是整条敲除。调用者传入的 `n_net` 是扫描上限。从第 23 张断开、并且前 22 张的 `.done` 和非空 `npz` 都在时，下次用同一个输出目录、`n_net` 至少为 23 再启动：第 1 到 22 张标成跳过，不重新抽样，也不再做 SVD。第 23 张若只有下标，就用这份下标重算这一张。第 24 张及以后按没有文件处理。`net_23` 这个文件名宽度够用。

这只覆盖建网。`scQC` 和 CPM 不在这个扫描里。从原始计数重新启动脚本时，这两步会再跑一遍；cLTMR 上它们不到 1 分钟。方向整理、对角线、敲除行置零、流形对齐和 `dRegulation` 没有中途文件。断在建网期间，这几步还没开始。

CP 的计算本身具备断点基础，代码还没写。它是三阶交替最小二乘：每一轮依次更新三个因子矩阵，然后用残差变化和 `td_maxError`（1e-05）比较，最多 `td_maxIter`（1000）轮。一轮完整结束后，要续上只需保存三个因子（大约 8000×3、8000×3、10×3）、`lambdas`、上一轮残差和轮次。输入仍是已经落盘的 10 张网，不必重算 SVD，也不必把整块 8000×8000×10 的张量再存一份。官方函数在一次 R 调用里跑完这个循环，中间不写这些因子。半轮保存不行：三个因子必须同属一轮结束时的值。初始因子来自 `set.seed(1)` 之后的 `rnorm`；从因子续跑就不再用这次随机数。

耗时上，已经分开记过的只有建网：正式 cLTMR 这一步超过 6 小时，整个亚群 474.7 分钟。15:11 日志仍停在建网，17:04 亚群结束，所以 CP 加上后面几步，连同 15:11 时还没写完的网，一起不到 1 小时 53 分钟。进度条在约 1% 时给出的 1–2 小时是按 1000 轮外推的，收敛时会直接跳到 100%，不能当成 CP 的实测用时。cLTMR 实际跑了多少轮没有记下。

图里的四步都在 CP 把 10 张网收成一张网之后：方向、对角线和敲除行是逐元素操作；W 的矩阵向量乘在合成矩阵上外推大约是 CPU 1 分钟、GPU 10 秒；低维坐标只有约 8000×2 个数；8000 个二维距离的实测是 CPU 0.000125 秒。这四步不是小时级。合成矩阵上，后半段里长的是 CP 的乘法：边长 5000、固定 40 轮，CPU 1 线程 199.130 秒，GPU 3.748 秒。外推到 8000 基因、仍是 40 轮，大约 CPU 8.5 分钟、GPU 10 秒。正式网络上的轮数和墙钟仍待测。

## 改造对照

每一项都先写现在是什么，再写改成什么。性能和准确性只写已经测过的数；没测的写待测，不把外推当成结果。

### 建网的分解

更改前：`pcNetCoreRcpp` 对每个基因做完整经济 SVD，再只留 3 个分量。正式 cLTMR 这一步超过 6 小时。当前加速代码在大矩阵上还会自动走 Gram。

更改后：调用者选定的那一台设备上，对设计矩阵做双精度直接截断 SVD，只留 3 个最大奇异方向，再用原来的系数公式。

原因：要的是设计矩阵本身的前 3 个奇异方向。Gram 会把条件数平方。完整 SVD 算完了绝大部分用不上的方向。

方式：每个基因删掉自己那一列，做截断 SVD，套现有系数公式。不按基因数自动选设备。

性能：1200 基因 × 150 细胞，官方 1 线程 77.3 秒，截断 1 进程 11.2 秒，4 进程 4.1 秒。400 基因 × 200 细胞，官方 21.5 秒，截断 1 进程 2.1 秒，4 进程 1.2 秒。Gram 在 cLTMR 一张网上大约 15 秒，那不是这条直接 SVD，不能当作改后性能。直接 SVD 的 GPU 墙钟待测。

准确性：1200 基因系数对 Rcpp 最大差 7.095e-16。400 基因、另一套种子，最大差 1.734e-15。Gram 对 CPU 截断抽查 10 个基因最大差 1.132e-16，没有覆盖 8000 个基因。直接 SVD 的 GPU 对 CPU、再对 Rcpp，待测。通过线仍是系数最大绝对差 < 1e-5。

### 落盘与续跑

更改前：官方一次调用中间不写网。中断后整个亚群重算。

更改后：上面的三件套。完成的网跳过，只有下标的网沿用下标。

原因：一张网的 SVD 很久，重算已完成的网没有新信息。

方式：下标在 SVD 前写。稀疏网和 `.done` 在算完后写。扫描在任何 SVD 之前。改造时补上 `genes`、`n_comp`、`q` 一致才跳过。

性能：两张小网的 `npz` 写入 3.38 毫秒、1.62 毫秒，发生在保存函数里，远小于该网的 SVD。8000 基因稀疏网的写入时间待测。

准确性：续跑不改已完成网的数值。F3 里保留的下标与删除前逐元素相同。参数核对本身不改矩阵；它只决定要不要重算。

### 数据放在哪一台设备

更改前：系数按批在 CPU 和 GPU 之间来回。后半段没有接到显卡。流程图曾误写成 10 张网结束就离开 GPU。

更改后：选 GPU 时，计数上传一次；每张网只再送细胞下标；SVD、删边、CP 乘法、W 的矩阵向量乘留在显存。稀疏网另拷一份到主机内存供落盘。距离在 CPU。选 CPU 时这些步骤都不上传。

原因：按基因来回搬会盖过计算。测试里更快的是建网、张量乘法和流形对齐的乘法。单独把矩阵搬上去做置零或距离，没有更快。

方式：一张网在选定设备上算完再下一张。10 张网的显存副本留给 CP。W 在显存里形成。只把低维坐标拷回主机做 `dRegulation`。

性能：0.5 GB 往返大约 0.02 秒，2.0 GB 往返大约 0.09–0.10 秒。5 GB 拷贝没有测完。边长 5000、40 轮的 CP 乘法，CPU 1 线程 199.130 秒，GPU 3.748 秒。10000 阶、4 个最小特征值，CPU 26.200 秒，GPU 3.915 秒。这两次是合成矩阵，流形探针是 `lobpcg`。正式网络上的墙钟待测。

准确性：搬运不改双精度的值。CP 和特征问题的公式保持官方定义。`lobpcg` 在对上 `RSpectra::eigs` 之前不作为对外结果。整条敲除的 `distance` 和 `p.adj < 0.05` 对照待测，规程 4.2 不能标通过。

### 百分比显示

更改前：进度曾经按基因写盘。80 基因 × 3 张网、每个基因都写盘时墙钟 0.397 秒；改成只在扫描和每张网落盘时写，墙钟 0.151 秒，写盘次数从 240 次降到 3 次。现在的百分比是终端里的 `基因 a/b`，默认每 100 个基因打印一行并 `flush`，不进 `进度_Progress.log`。

更改后：百分比仍只在终端显示。距上次打印至少 2 秒，并且完成比例至少再增加 5%，两个条件都要满足；这一张网算完时再打一行。不写入 `进度_Progress.log`。GPU 在该基因的系数行已经回到主机之后才调用回调，不为百分比单独做一次同步。

原因：`flush` 到被别的程序盯着的终端时，打印会堵住计算。百分比不参与系数。

方式：`Progress.gene` 里用同一把锁记下上次打印的时间和比例，未到间隔就直接返回。计算循环不打开进度文件。

性能：逐基因写盘的 0.397 秒对 0.151 秒是更早的测量。这次收稀之后，8000 基因上的墙钟差待测。25 基因自测的进度日志里仍然没有逐基因行。

准确性：显示文字不进入矩阵。25 基因这次自测，系数对 `pcNetCoreRcpp` 的最大差 3.273e-15，网络对 `pcNet` 的最大差 1.033e-14。

## 这次写入代码的改动

下面四项已经进 `knk_accel`。Formal 的 13 号脚本和它的结果目录没有动。测量用 1 个 BLAS 线程，矩阵都是合成的。原始输出在 `断点与直接SVD_ResumeSvd.md`。

### 直接截断 SVD 替换 Gram

更改前：`device="auto"` 在基因数不少于 1000、细胞数不少于 200 时，用双精度 Gram 再求特征值。

更改后：只有 `device="gpu"` 才用显卡。每个基因对删掉自身列之后的设计矩阵做双精度 `svd`，留前 3 个右奇异向量，再套原来的系数公式。`auto` 留在 CPU。`gpu` 且 `n_workers` 不是 1 时直接报错，避免子进程再打开 CUDA。

原因：Gram 把条件数平方。按规模自动切设备也和已敲定的调用方式不一致。

方式：一张网在调用者选定的一台设备上逐基因分解。这一步仍把每个基因的系数行拷回主机；整网留在显存留给后面的搬运，没有混进这次。

性能：24 基因 × 30 细胞，CPU 0.014 秒，GPU 0.311 秒。这张小矩阵上 GPU 更慢，所以默认不进显卡。8000 基因的直接 SVD 墙钟待测。以前 Gram 的约 15 秒不能当作这次的性能。

准确性：同一矩阵 GPU 对 CPU 系数最大绝对差 6.731e-15，低于 1e-5。不是 8000 基因，也没有因此替换 Formal。

### 异步保存的进程安全

更改前：写盘在一个后台线程里，传入的是计算刚得到的稀疏矩阵和调用方的下标数组。进度文件的追加没有锁。

更改后：提交写盘之前先做稀疏矩阵、下标和基因名的深拷贝。写盘线程只有 1 个，线程名 `knk_save`，不创建进程，也不打开 CUDA。进度文件的替换和日志追加共用一把可重入锁。`npz` 和 `.done` 仍是写临时文件再 `os.replace`。

原因：计算线程如果接着改同一块缓冲，写盘会把下一张网的数写进上一张。两个线程同时追加日志会交错。

方式：副本属于写盘线程。主线程可以继续改自己的矩阵。CP 的检查点不走这个线程：每一轮结束后在调用线程上先复制因子，再原子写入，然后才开始下一轮。因子大约是两块 8000×3 加一块 10×3，写入本身很短，异步反而要多防一次共享。

性能：深拷贝和加锁的额外墙钟没有单独测。以前两张小网的 `npz` 写入是 3.38 毫秒和 1.62 毫秒。

准确性：副本测试里，原矩阵改成 0 之后，副本右下角仍是 2。数值公式没有改。

### 建网参数不一致时不跳过

更改前：只要 `.done` 和非空 `npz` 都在就跳过，不看 `q` 和基因名。

更改后：跳过还要求 `genes`、`n_comp`、`q` 与本次调用一致。不一致就删除 `.done`，下标还在则沿用下标重算。

原因：文件在但参数变了，跳过会把旧网当成新结果。

方式：只读 `npz` 里已经有的字段，不改三件套的格式。

性能：多读最多 `n_net` 个小文件头。10 张网的额外时间待测，预期远小于 SVD。

准确性：小测里 `q` 从 0.9 改成 0.95，完成标记被去掉，动作变为沿用下标。已完成且参数相同的网仍跳过；04 自测删掉第 2 张后，下标不变，另外两张跳过。

### CP 按轮续跑

更改前：加速库里没有 CP。官方循环在一次 R 调用内跑完，中断后从随机初始因子重来。

更改后：三阶交替最小二乘，一轮内依次更新三个因子再算残差。该轮结束后把因子、`lambdas`、上一轮残差、下一轮轮次和张量摘要原子写入 `npz`。摘要不一致就拒绝续跑，不从别人的因子接着算。`max_iter` 变大可以继续；变小则不再多跑。`device="gpu"` 用同一公式的双精度乘法，检查点仍写在主机上。

原因：一轮的状态只有三块小因子，输入是已经落盘的网，不必重做 SVD。半轮不能存，所以写在三个因子都更新完之后。

方式：调用线程同步写。下一轮使用新的数组，不和文件缓冲共享内存。初始因子默认来自 NumPy 的 `default_rng(seed)`，不是 R 的 `rnorm` 序列；要和一次跑完的结果比较时，两次传入同一组初始因子。

性能：16×16×4、固定 4 轮，CPU 不到 0.001 秒，GPU 0.042 秒。这是小张量，不能外推到 8000 基因。边长 5000、40 轮的旧探针仍是 CPU 199.130 秒、GPU 3.748 秒，那次不是这个带检查点的实现。

准确性：先跑到 `max_iter=3`（两轮更新）再续到 `max_iter=5`，与一次跑到 `max_iter=5` 的第一因子最大绝对差 0。GPU 对 CPU 的重构最大绝对差 1.221e-15。还没有对官方 `cpDecomposition` 的 `rnorm` 初值逐轮对照，所以不能称为已替换官方 CP。

### GPU 的 SVD 从 Jacobi 改为 gesvd

更改前：`torch.linalg.svd` 不指定 `driver`。CUDA 上这是 cuSOLVER 的 Jacobi（`gesvdj`）。cLTMR 质控矩阵经 CPM 后，基因下标 0、10、100、1000、4000、7999，对 R `svd` 最大绝对差 6.054e-16，对 CPU 最大绝对差 6.042e-16，6 个基因 1.523 秒。

更改后：显式 `driver="gesvd"`，仍是设计矩阵的双精度直接截断 SVD，系数公式不变，仍在显卡上算完。同一批基因对 R 最大绝对差 1.902e-16，对 CPU 1.230e-16，GPU 0.978 秒，显存峰值 571.4 MB。CPU 对 R 是 1.081e-16。24 基因 × 30 细胞，GPU 对 CPU 6.019e-15。原始输出在 `GPU求解器_Gesvd.md`。

原因：Jacobi 和 LAPACK 的舍入不在同一条路径上，所以比 CPU 对 R 的 1e-16 大约多几倍。`gesvd` 是 QR 迭代，和 R / CPU 用的经济 SVD 更接近。没有改成 128 位，也没有改系数公式。

方式：一个基因的分解整段留在显卡。没有采用「显卡 QR、CPU `gesdd` 分解 407×407 三角因子」：那条对 CPU 的差是 1.298e-16、6 个基因 0.704 秒，但会把一个基因的 SVD 拆到两台设备。把 Jacobi 的系数公式挪到 CPU 只从 6.042e-16 变成 6.039e-16，所以公式留在显卡。

性能：这 6 个基因从 1.523 秒降到 0.978 秒。不是 8000 基因的整网时间。小矩阵上 GPU 仍慢于 CPU（0.067 秒对 0.020 秒）。

准确性：1.902e-16 低于 1e-5。和 CPU 对 R 的 1.081e-16 在同一档，GPU 仍大约大不到两倍。只覆盖 6 个基因，不能外推到全部 8000 个。没有重算 `distance` / `p.adj`。

2026-10-02 的举证运行写在 `烟测断点举证_SmokeResume.md`。cLTMR 已于 2026-10-01 17:04:48 结束。建网断点：删掉第 2 张后再跑，第 1、3 张哈希不变，第 2 张下标逐元素相同。CP 断点：续跑与一次跑完的因子差为 0，错误摘要被拒绝。cLTMR 质控矩阵 6 个基因的留一系数，CPU 对 R `svd` 最大差 1.141e-16，GPU 对 R 最大差 6.054e-16。官方 `distance` / `p.adj` 没有重算。百分比的打印间隔写在 `百分比烟测_PercentSmoke.md`：未满 2 秒不打印，满 2 秒且到 5% 才打印，结束时再打印，进度日志没有逐基因行。当时 Jacobi 路径对 R 的差是 6.054e-16，没有改系数公式。求解器后来改成 `gesvd`，见上一节。
