# 终态收尾与 GMX_MAXBACKUP — 调研（2026-10-10）

问题：chunk MD 跑到 100 ns 后因 `Won't make more than 99 backups of md.gro` Fatal，无 `DONE`——是否等于“不收敛”、是否须重跑？

## 结论（先读）

| 问题 | 答案 |
|------|------|
| 官方如何看这个 Fatal？ | **输出文件备份上限**，与积分/采样无关；用 `GMX_MAXBACKUP=-1` 覆盖，或不再依赖每次 chunk 写 `md.gro` |
| 期刊是否要求“成功写出最终 md.gro”？ | **否**。看重的是轨迹长度、副本、可复现与可观测量是否稳定；分析对象是 **轨迹（xtc/trr）+ 能量（edr）**，不是最后一次 gro 备份是否成功 |
| 须否重跑 100 ns？ | **否**。`md.log` 已到 `Time=100000` 且已写 checkpoint；用 `gmx trjconv -dump` 抽末帧即可 |

## 1. GROMACS 官方

### 1.1 `GMX_MAXBACKUP`

手册（[Environment Variables](https://manual.gromacs.org/current/user-guide/environment-variables.html)）：

- 写同名输出时自动备份旧文件；**默认最多 99 个备份**
- `0`：若输出已存在则失败
- **`-1`：覆盖输出、不做备份**

本次 Fatal 文案与手册一致：第 100 次写 `md.gro` 触发上限，发生在 **已写出 `Writing checkpoint, step 50000000`（100 ns）之后**。

### 1.2 如何从轨迹取终态（官方工具）

[`gmx trjconv`](https://manual.gromacs.org/current/onlinehelp/gmx-trjconv.html)：`-dump <time_ps>` 抽取最接近该时间的帧。  
[`gmx check -f md.xtc`](https://manual.gromacs.org/current/onlinehelp/gmx-check.html)：核对轨迹时间范围。  

GROMACS 维护者 Mark Abraham 在用户列表说明：没有“自动最后一帧”的捷径时，先 `gmx check` 再 `trjconv -dump`（[mail archive](https://www.mail-archive.com/gromacs.org_gmx-users@maillist.sys.kth.se/msg36623.html)）。  
对本案已知终点为 100000 ps：

```bash
export GMX_MAXBACKUP=-1
echo 0 | gmx trjconv -s md.tpr -f md.xtc -o md_final.gro -dump 100000
```

不必为拿终态结构而重跑生产段。

## 2. 高分 / 主流期刊与最佳实践要什么

期刊与 LiveCoMS 讨论的是 **采样与可复现**，不是 gro 备份。

### 2.1 JCIM 编辑指南（ACS）

*Guidelines for Reporting Molecular Dynamics Simulations in JCIM Publications*（[JCIM 2023](https://pubs.acs.org/doi/10.1021/acs.jcim.3c00599)）：

- Methods 须写清体系、力场、系综、软件版本、平衡/生产设置等  
- **至少 3 条 replica**（宜不同初坐标/初速度），报告方差；披露随机种子  
- **存档**：拓扑、参数、输入、初态与轨迹（或代表性帧）到带 DOI 的仓库  

未要求“最终坐标文件必须由 mdrun 正常退出写出”。

### 2.2 Nature 系可复现清单

*Communications Biology* MD reliability checklist（[表 1](https://www.nature.com/articles/s42003-023-04653-0/tables/1)）强调：

1. 所测性质是否已平衡（时间曲线）  
2. 平衡段 vs 生产段如何划分、分析用多少生产数据  
3. ≥3 次独立模拟与统计  
4. 结果对初态是否稳健  

同样不涉及“末帧 gro 是否备份成功”。

### 2.3 “收敛”在文献里指什么

- *Communications Chemistry* 等：常用能量 / RMSD 时间曲线看是否进入平台，但更严格的是 **目标观测量** 的采样质量；长时标蛋白未必真正平衡（[2024 评述](https://www.nature.com/articles/s42004-024-01114-5)）。  
- 仅凭 RMSD“看起来平了”判断平衡 **不可靠**（[Knapp et al., BMC Bioinformatics](https://pmc.ncbi.nlm.nih.gov/articles/PMC3145956/)）。  
- LiveCoMS *Best Practices for Quantification of Uncertainty and Sampling Quality*：先评估采样，再估观测量与不确定度。

→ **“脚本没 DONE / gro 备份失败”≠文献意义上的不收敛。**  
收敛要另看：蛋白/配体 RMSD、COM、结合相关观测量在生产段是否稳定，以及是否具备多副本。

## 3. 对本项目的落地建议

1. **立即收尾（不重跑）**  
   - `GMX_MAXBACKUP=-1`  
   - `trjconv -dump 100000` → `md_final.gro`（或覆盖 `md.gro`）  
   - 可选：对完整 `md.xtc` 再跑一次 monitor；写 `DONE.txt` 注明“100 ns complete; gro from trjconv after MAXBACKUP abort”

2. **流水线防再发**（SOP 级，已落地 2026-10-10）  
   - `运行复合物MD_runComplexMd.sh` 默认 `GMX_MAXBACKUP=5`（保留少量备份；可用环境变量改）  
   - 生产满后若无 `md.gro`：用 `trjconv -dump`；现成目录用 `环境安装_EnvSetup/finalize_100ns_wrap.sh`  
   - 监控忽略「backups / GMX_MAXBACKUP」类 Fatal

3. **投稿口径**（若走 JCIM/同类）  
   - 报告 100 ns 生产、软件版本、监控指标；补 ≥3 replicas 与存档计划  
   - Methods 可写：轨迹完整至 100 ns；终态坐标由轨迹末帧提取（因自动备份上限）——属工程细节，不影响声明生产时长
