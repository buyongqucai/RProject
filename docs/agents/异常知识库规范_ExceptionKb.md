# 异常知识库规范（Exception KB）— SSOT

> **地位：** 全部分析技能 `异常知识库_ExceptionKB/` 文件夹的唯一写法规范。  
> **目的：** 每个异常经历一次，全库复用——**如何判定**（真异常还是假象）、**如何补救**（可执行路径）、**何时放弃**（无补救才弃）。  
> **进化：** 你确认新约定后只改本文件；技能说明与范式清单只留指针（项目规范 §0）。

## 1. 目录约定（每个技能根）

```text
<技能>/
  异常知识库_ExceptionKB/
    README.md            # 本技能案例索引表 + 一行指针指向本文件
    案例_Cases/
      01-<症状关键词>.md  # 每个异常一例，序号递增，中文主题词
```

- 没有案例时：保留 `README.md`（空索引），**不要**建空案例文件。
- 案例只增不删；案例被工具修复后**保留**，在补救段注明「已在 <脚本/门禁> 自动化」。

## 2. 案例模板（`案例_Cases/NN-*.md`）

```markdown
# <症状一句话>

- 日期/体系：YYYY-MM-DD；<体系/样本名>
- 状态：已解决 | 已自动化 | 观察中 | 无补救已弃

## 症状（怎么发现的）
报错原文 / 指标越界值 / 日志关键行（保留可检索的英文原文）。

## 判定（真异常还是假象）
判定树：先查什么、再查什么；**决定性证据**是什么（哪个命令/指标一锤定音）。
- 假象特征（如 PBC 伪影、备份上限 Fatal）与真实故障特征的分界。

## 补救（按序尝试）
1. …（可复制命令/脚本入口）
2. …
## 何时放弃
什么证据出现后不再补救（换结构/换姿态/换路线），避免无限重试。
## 复盘（根因一句话 + 预防）
根因；已加的门禁/脚本；下一次如何 1 分钟识别。
```

## 3. 写入纪律

1. **触发：** 任何异常**关闭后 24h 内**落档（含假象类）；工单 `.scratch/` 完成时顺手落案例。
2. **判定优先：** 案例必须含「判定」段——禁止只写补救命令不写如何确认。
3. **保留原文：** 报错/指标写英文原文（可 grep），中文只作解释。
4. **单一事实：** 修复规则若升级为 SOP/门禁，案例里只留指针（如 `复合物MD流水线_GromacsSop.md §9.0.x`）。
5. **秘密不入库：** 凭据/授权码一律不写入案例（同 QQ 邮箱凭据禁入库规则）。

## 4. 与工单/审计联动

- `.scratch/<功能>/issues/` 单据验收含「案例是否入库」；假象类异常同样入库。
- 技能逐文件审计（`技能范式清单` E 节）时检查：`异常知识库_ExceptionKB/README.md` 索引与 `案例_Cases/` 一致。
