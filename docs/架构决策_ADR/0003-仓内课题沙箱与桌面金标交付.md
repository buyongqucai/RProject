# 0003 — 仓内课题沙箱 vs 桌面金标交付

- 日期：2026-09-06
- 状态：已接受（审计后用户要求全部修复边界冲突）

## 背景

`CONTEXT.md` / `项目规范` 写明交付项目在桌面独立成库、各自 git；仓库内却长期存在 `努力学习项目/` 等课题目录，造成 agent 对「该不该进本仓 git、算不算金标」判断分裂。

## 决策

区分两类路径：

| 类型 | 位置 | git | 用途 |
|------|------|-----|------|
| **金标交付** | 桌面独立目录（如 `痤疮_分子对接_序号文件夹/`、`杨程茗分子对接/`） | **各自独立仓库** | 客户/课题正式交付，对齐技能金标 |
| **仓内课题沙箱** | `E:\RProject/<课题名>/`（如 `努力学习项目/`） | **可进本仓**，但只跟踪脚本/清单/小表/README；大体积图（KEGG PNG/GIF 等）默认 `.gitignore` | 与技能库同仓迭代、方便对照脚本 |

## 理由

- 金标必须可整夹移交，不宜绑在技能库历史上。  
- 沙箱需要与 `生信分析技能_BioinformaticsSkills` 同仓改脚本，强行迁出反而阻碍「反馈→改技能」闭环。  
- 大体积产物不进 git，避免远程爆炸，同时保留可复现的小文件线索。

## 影响

- Agent：改交付样式以**桌面金标**为准；改脚本/SOP 以技能库为准；沙箱产物缺图时不得编造，只标缺文件。  
- `.gitignore` 显式忽略沙箱内 KEGG 等大图；`.scratch` 二进制探针忽略，markdown 议题可保留。
