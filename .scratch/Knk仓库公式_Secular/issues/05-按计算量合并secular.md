# 05: 按计算量选择 secular 的合并方式

**类别:** enhancement
**标签:** 已完成
**Blocked by:** None

**What to build:** 建网前用特征值个数、基因数和 nComp 估计 secular 的计算量，再决定走原来的多次 GPU 调用，还是合成一个双精度 CUDA 核。公式不变。测小矩阵和约 8000 基因的误差与用时。1 个 BLAS 线程，不写 Formal 结果。

- [x] 有计算量评估和选择结果
- [x] 合并后的系数对未合并版本，最大绝对差 < 1e-5
- [x] 记下小矩阵和大矩阵上谁更快

## Notes

评估量是特征值个数 × 基因数 × nComp × 300。这张 4080 上 40×30、800×200、8000×425 都是合并更快，最大差约 1e-17。GPU 的 auto 因此选择合并。记录在 `文档_docs/合并策略_SecularMerge.md`。
